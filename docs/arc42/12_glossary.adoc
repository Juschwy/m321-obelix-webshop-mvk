== Glossary

This section defines the **most important domain and technical terms** used in the Obelix application.
It ensures all stakeholders have a **shared understanding** and avoids ambiguity.

[cols="e,2e", options="header"]
|===
|Term |Definition

|Hinkelstein
|Product sold in the webshop; domain object managed by the quarry service.

|Obelix Webshop
|The overall application consisting of frontend and backend microservices.

|MAAS (Metal as a Service)
|Infrastructure used to provision VMs; BBW-Maas is the school-managed instance.

|Docker Compose
|Container orchestration used to run all services on the VM.

|GHCR (GitHub Container Registry)
|Registry where Docker images are published.

|Zipkin
|Distributed tracing system that collects spans from backend services.

|Prometheus
|Metrics collection system that scrapes /actuator/prometheus endpoints.

|Grafana
|Visualization tool for Prometheus metrics.

|OpenAPI (OAS 3.x)
|API specification describing REST endpoints; generated code-first per microservice.

|Code-first API
|Approach where API documentation is generated from source code annotations.

|Reverse Proxy (Gateway)
|obelix-webshop component that routes/aggregates frontend requests to domain services.

|WireGuard
|VPN used to securely connect CI/CD to the VM for deployment.

|Actuator (/prometheus)
|Spring Boot endpoint exposing metrics for Prometheus.

|CI/CD
|Automated processes for building, testing, and deploying the application via GitHub Actions.

|BBW (Berufsbildungsschule Winterthur)
|The school operating the MAAS environment used for this project; provides the infrastructure context.
|===
