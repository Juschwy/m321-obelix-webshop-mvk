== Building Block View

This chapter describes the **static decomposition** of the system into building blocks.
It serves as a **shared template** and is intentionally abstract.
Concrete building blocks and details must be added by the responsible teams.

The goal is to keep the structure consistent and easy to extend.

==== Motivation

The system is split into a single-page frontend and multiple backend microservices to allow parallel development by a large team and clear separation of responsibilities. A reverse proxy (obelix-webshop) aggregates calls to domain services (quarry, basket). Observability is built-in with Zipkin (traces) and Prometheus/Grafana (metrics) to meet the assignment requirements and support troubleshooting.

==== Contained Building Blocks

[cols="1,2",options="header"]
|===
|Name |Responsibility

|Frontend (Angular + Nginx)
|Customer-facing UI for browsing and purchasing Hinkelsteine; uses generated OpenAPI client.

|obelix-webshop (reverse proxy)
|Gateway for frontend; routes/aggregates requests to basket/quarry; exposes /actuator/prometheus metrics.

|obelix-quarry
|Provides product (Hinkelstein) data and APIs.

|obelix-basket
|Manages shopping baskets and operations.

|Prometheus
|Scrapes metrics from backend services and itself.

|Zipkin
|Collects distributed traces from backend services.

|Grafana
|Visualizes Prometheus metrics.
|===

==== Important Interfaces

* Public REST APIs per microservice (OpenAPI 3.x, code-first via springdoc)
* Frontend consumes backend via generated OpenAPI client
* Monitoring endpoints: /actuator/prometheus on backend services
* Tracing: Zipkin HTTP span ingestion API (port 9411)
* Internal service contracts: Shared Java interfaces (in shared modules) define reverse-proxy-to-microservice contracts; HTTP clients in obelix-webshop implement these interfaces to call obelix-quarry and obelix-basket.

=== Level 1 – Black Box Descriptions

== Frontend (Angular + Nginx)

=== Purpose / Responsibility
Customer-facing Web UI. The frontend is a single-page application that uses a generated OpenAPI client to communicate with the backend via the reverse proxy.

=== Interfaces
*Provided:* Web UI (HTTP)
*Consumed:* `obelix-webshop` REST API

=== Quality / Performance Characteristics
Static content is served via Nginx. All dynamic data is retrieved from backend services.

=== Implementation Details
This documentation provides a focused view on the Customer Web UI located under `frontend/obelix-webshop-frontend`:

* Angular 21 single-page application using standalone components and Signals
* Client-side state management for the shopping cart combining Signals and NgRx Store
* Backend communication exclusively through an OpenAPI-generated Angular client
* Build and runtime handled via Node.js / Angular CLI during development and Nginx in the production Docker image

=== Location
`frontend/obelix-webshop-frontend`

==== obelix-webshop (reverse proxy)

*Purpose / Responsibility*
Aggregates and routes frontend requests to basket/quarry; exposes metrics and sends traces to Zipkin.

*Interfaces*
Provided: REST API for frontend.
Consumed: obelix-basket, obelix-quarry REST APIs; Zipkin ingestion API.
Internal contracts: Implements shared Java interfaces for basket/quarry clients to ensure consistent method signatures and behaviors.

(Optional) *Quality / Performance Characteristics*
Single point of entry; ensures consistent APIs.

(Optional) *Location*
backend/obelix-webshop

==== obelix-quarry

*Purpose / Responsibility*
Product data and CRUD APIs.

*Interfaces*
Provided: REST API; /actuator/prometheus.
Consumed: Zipkin ingestion API.
Internal contracts: Exposes and adheres to shared Java interfaces used by the gateway client.

(Optional) *Location*
backend/obelix-quarry-impl

==== obelix-basket

*Purpose / Responsibility*
Basket management and CRUD APIs.

*Interfaces*
Provided: REST API; /actuator/prometheus.
Consumed: Zipkin ingestion API; obelix-quarry API.
Internal contracts: Exposes and adheres to shared Java interfaces used by the gateway client.

(Optional) *Location*
backend/obelix-basket-impl

==== Prometheus

*Purpose / Responsibility*
Collects metrics.

*Interfaces*
Consumed: /actuator/prometheus endpoints of backend services.

==== Grafana

*Purpose / Responsibility*
Metrics visualization.

*Interfaces*
Consumed: Prometheus HTTP API.

==== Zipkin

*Purpose / Responsibility*
Trace collection.

*Interfaces*
Provided: HTTP span ingestion (port 9411).
Consumed: spans from backend services.
