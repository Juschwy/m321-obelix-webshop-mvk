== Building Block View

This chapter describes the **static structure** of the Obelix application.
It shows the system decomposition into building blocks and their responsibilities.
The focus is on **understanding**, not on implementation details.

=== Whitebox Overall System

==== Overview Diagram

[plantuml, building-block-overview, svg]
----
@startuml
rectangle "Obelix Application" {

  rectangle "Customer Web UI" as FE_Customer
  rectangle "Admin Web UI" as FE_Admin

  rectangle "Backend" {
    rectangle "Product Service"

    rectangle "Admin Service"
  }
}

FE_Customer --> "Product Service"
FE_Customer --> "Order Service"

FE_Admin --> "Admin Service"

@enduml
----

==== Motivation

The system is decomposed into **independent frontend and backend building blocks**
to support parallel development, clear responsibilities, and scalability.

Backend functionality is split into **multiple microservices** to comply with the
architectural constraints and to enable independent deployment and monitoring.

==== Contained Building Blocks

[cols="1,2",options="header"]
|===
|Name |Responsibility

|Customer Web UI
|Provides a web-based user interface for customers to browse and order Hinkelsteine.

|Admin Web UI
|Provides a web-based user interface for administrators to manage Hinkelsteine (CRUD).

|Product Service
|Manages Hinkelstein product data and provides read access for customers and admins.

|Order Service
|Handles order creation and order-related business logic.

|Admin Service
|Provides administrative operations for managing products.
|===

==== Important Interfaces

* REST APIs exposed by backend services (documented via OpenAPI 3.x)
* Generated OpenAPI clients used by both frontend applications
* HTTP-based metrics and tracing endpoints (Prometheus, Zipkin)

=== Level 1 – Black Box Descriptions

==== Customer Web UI

*Purpose / Responsibility*  
Provides a browser-based interface for customers to view available Hinkelsteine and place orders.

*Interfaces*  
Consumes REST APIs of Product Service and Order Service via generated OpenAPI client.

*Quality Characteristics*  
Usability and responsiveness are prioritized.

---

==== Admin Web UI

*Purpose / Responsibility*  
Provides a browser-based interface for administrators to manage Hinkelsteine.

*Interfaces*  
Consumes REST APIs of the Admin Service via generated OpenAPI client.

---

==== Product Service

*Purpose / Responsibility*  
Stores and provides access to Hinkelstein product data.

*Interfaces*  
REST API (OpenAPI 3.x) for product queries and administration.

---

==== Order Service

*Purpose / Responsibility*  
Processes customer orders and manages order-related data.

*Interfaces*  
REST API (OpenAPI 3.x) for order creation and retrieval.

---

==== Admin Service

*Purpose / Responsibility*  
Central service for administrative CRUD operations on products.

*Interfaces*  
REST API (OpenAPI 3.x) for administrative actions.

---
