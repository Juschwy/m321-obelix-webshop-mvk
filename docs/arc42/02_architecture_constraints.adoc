== Architecture Constraints

This chapter lists **external constraints** imposed on the project from outside the team.
These are non-negotiable limitations we must work within.

---

=== Infrastructure Constraints (BBW-Maas)

[cols="1,2",options="header"]
|===
|Constraint |Description / Impact

|BBW-Maas platform only
|We are required to use BBW-Maas for hosting. No alternative cloud providers or on-premise options allowed.

|Ephemeral VMs (auto-deletion)
|VMs are automatically deleted after a set period. No persistent infrastructure; deployments must be repeatable and automated.

|Single VM allocation
|Only one VM is provided per project. No horizontal scaling or multi-node setups possible.

|No control over VM resources
|VM sizing (CPU, RAM, disk) is fixed by MAAS administration. We cannot request larger instances.

|Ubuntu 24.04 only
|Operating system is predetermined; no choice of OS or version.

|No guaranteed uptime
|Infrastructure is for educational purposes; outages and resets are expected.
|===

---

=== Time & Resource Constraints

[cols="1,2",options="header"]
|===
|Constraint |Description / Impact

|Limited project timeline
|Strict deadline imposed by module schedule. No time for extensive exploration or rework.

|Small team size (~17 people)
|Limited workforce distributed across all tasks (frontend, backend, docs, DevOps). Parallel work is essential.

|Limited working hours
|Team members are students with other commitments; availability is constrained.
|===

---

=== Technical Requirements (Given/Predefined)

[cols="1,2",options="header"]
|===
|Constraint |Description / Impact

|Backend services predefined
|Backend architecture and service structure (webshop, quarry, basket) are given. We implement within this structure, not redesign it.

|OpenAPI interface mandatory
|Frontend-backend communication must use OpenAPI specification. Frontend generates client from OAS definitions.

|GitHub repository (user-level)
|We only have access to a user-owned GitHub repository, not an organization. Limits some GitHub features.

|Docker Compose for orchestration
|Deployment method is prescribed; Kubernetes or other orchestrators are not permitted.

|Observability stack prescribed
|Must use Zipkin (tracing), Prometheus (metrics), and Grafana (dashboards). No alternative tools allowed.

|===

---

=== Organizational Constraints

[cols="1,2",options="header"]
|===
|Constraint |Description / Impact

|Protected main branch
|All changes require pull requests with mandatory reviews. Direct commits to main are blocked.

|Documentation format prescribed
|Must use AsciiDoc with arc42 template structure. No Markdown or other formats for architecture docs.
|===

---

=== Summary of External Limitations

* **We cannot change**: hosting platform, VM resources, backend structure, API specification format, tooling choices
* **We must accept**: ephemeral infrastructure, limited time, small team, predefined architecture
* **We control**: implementation details within given constraints, code quality, documentation content
