=== Observability (Metrics & Tracing)

==== Purpose / Motivation

Provide unified monitoring and tracing across all services to meet assignment requirements and support troubleshooting in dev/test.

==== Affected Building Blocks

* obelix-webshop, obelix-quarry, obelix-basket
* Prometheus, Grafana, Zipkin

==== Description

* Metrics are exposed via Spring Boot Actuator (/actuator/prometheus) on backend services and scraped by Prometheus.
* Grafana visualizes metrics from Prometheus.
* Traces are sent via HTTP to Zipkin (port 9411) using Spring Cloud Sleuth/Micrometer tracing configuration.

==== Notes / Guidelines

* Ensure each service exposes /actuator/prometheus.
* Zipkin endpoint: http://zipkin:9411/api/v2/spans (configured via MANAGEMENT_ZIPKIN_TRACING_ENDPOINT).

'''

=== API Strategy (OpenAPI & Clients)

==== Purpose / Motivation

Guarantee consistent and documented APIs; enable frontend to use generated clients.

==== Affected Building Blocks

* All backend microservices
* Frontend (Angular)

==== Description

* OpenAPI 3.x specifications are generated code-first (e.g., springdoc).
* Frontend uses a client generated from OpenAPI definitions (openapi-generator) to call the reverse proxy.
* All properties in OAS must have descriptions and examples.

'''

=== Configuration & Deployment

==== Purpose / Motivation

Ensure reproducible deployments to the BBW-Maas VM with minimal overhead.

==== Affected Building Blocks

* All services
* CI/CD pipeline

==== Description

* Docker Compose orchestrates all containers on a single Ubuntu 24.04 VM.
* Images are built and published to GHCR via GitHub Actions.
* VM provisioning via MAAS API; updates via WireGuard + SSH; compose executed with `docker compose up -d`.

'''

=== Security Posture (Dev/Test)

==== Purpose / Motivation

Clarify simplified security model for a dev/test environment.

==== Description

* Admin UI has CRUD without authentication or sessions.
* No external exposure beyond necessary HTTP ports on the VM.
* Tracing/metrics endpoints accessible within Docker network.

'''

=== CI/CD & Collaboration

==== Purpose / Motivation

Maintain quality and collaboration across a large team.

==== Description

* Protected main branch; all changes via PR with three mandatory reviews.
* Automated tests and builds on PR; deployments on main.
* Ownership defined via OWNERS/CODEOWNERS.

=== Backend Internal Contracts (Shared Java Interfaces)

==== Purpose / Motivation
Ensure consistent and type-safe contracts between the reverse proxy and microservices without relying solely on REST specs.

==== Affected Building Blocks
* obelix-webshop (clients)
* obelix-quarry, obelix-basket (implementations)
* Shared modules (e.g., obelix-common, API modules)

==== Description
* Java interfaces are defined in shared modules to express service contracts.
* Clients in obelix-webshop implement these interfaces to call downstream services.
* This approach complements OpenAPI by providing compile-time guarantees across modules.

==== Notes / Guidelines
* Keep interfaces stable; version carefully.
* Align interface contracts with REST endpoints to avoid drift.
