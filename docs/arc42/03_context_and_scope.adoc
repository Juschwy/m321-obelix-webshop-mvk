== Context and Scope

This section describes the **system context** of the Obelix application.
It defines the system boundaries and identifies all relevant communication partners.
The goal is to clarify **who interacts with the system and how**, both on a business and a technical level.

=== Business Context

The Obelix application is a web-based system for selling and managing Hinkelsteine.
It is used by customers and administrators and provides domain-specific functionality
related to ordering and managing products.

==== Business Context Overview

[cols="1,2,2",options="header"]
|===
|Communication Partner |Inputs to Obelix |Outputs from Obelix

|Customer
|Product selection, order requests
|Product listings, order confirmations

|Administrator
|CRUD operations on Hinkelsteine
|Updated product data, management views

|External Developer
|API requests (REST)
|API responses (JSON)

|CI/CD Pipeline
|Source code, configuration
|Build artifacts, deployment results
|===

==== Business Context Diagram

[plantuml, business-context, svg]
----
@startuml

rectangle "Obelix Application" {
}

Customer --> "Obelix Application" : browse & order Hinkelsteine

@enduml

==== Explanation

* The Obelix application is treated as a **black box** in the business context.
* No authentication or authorization is applied.
* External developers interact exclusively via the published API.

The technical context describes **how** communication with the Obelix system is realized,
including protocols, data formats, and infrastructure components.

|JSON

|External Systems / Clients
|HTTPS (REST, OpenAPI)
|JSON

|Monitoring Stack
|HTTP
|Metrics (Prometheus format)

|Tracing data
|===

==== Mapping: Input / Output to Channels

[cols="2,2,2",options="header"]
|===
|Business Interaction |Technical Channel |Protocol / Format

|Browse products
|Customer Web UI → Backend
|HTTPS / JSON

|Manage Hinkelsteine
|Admin Web UI → Backend
|HTTPS / JSON

|API integration
|External Client → Backend
|HTTPS / REST (OpenAPI)

|Metrics collection
|Backend → Prometheus
|HTTP / Metrics format

|Distributed tracing
|Backend → Zipkin
|HTTP / Trace data
|===

==== Notes

* All external communication uses **HTTP(S)**.
* REST APIs are documented via **OpenAPI 3.x**.
* The frontend uses **only generated API clients**.
* No message queues or asynchronous messaging are used at this stage.
